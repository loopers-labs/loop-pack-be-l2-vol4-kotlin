# 요구사항 명세서

## 설계 전제

- 한 번의 주문에 여러 상품을 담을 수 있다.
- 상품 목록은 브랜드와 카테고리 기준으로 필터링할 수 있다.
- 좋아요 취소 시 이력을 남기지 않는다.

## 유저 시나리오 및 요구사항 명세

---

### F-01. 상품 목록 조회

**시나리오**
> 고객이 앱에 접속해 상품을 탐색한다. 원하는 브랜드나 카테고리를 선택해 범위를 좁혀볼 수 있다.

**요구사항**

| ID | 내용 |
|----|------|
| F-01-1 | 상품 목록은 페이지 단위로 나눠서 볼 수 있다. |
| F-01-2 | 브랜드를 선택해 해당 브랜드의 상품만 볼 수 있다. |
| F-01-3 | 카테고리를 선택해 해당 카테고리의 상품만 볼 수 있다. |
| F-01-4 | 브랜드와 카테고리를 동시에 적용해 필터링할 수 있다. |
| F-01-5 | 판매 중단된 상품은 목록에 노출되지 않는다. |
| F-01-6 | 재고가 없는 상품은 품절 상태로 목록에 노출된다. |

**목록에서 확인할 수 있는 정보**: 상품명, 가격, 브랜드명, 카테고리명, 재고 여부, 좋아요 수

---

### F-02. 상품 상세 조회

**시나리오**
> 고객이 목록에서 상품을 선택해 상세 정보를 확인한다. 로그인한 고객은 자신이 좋아요를 눌렀는지 여부도 함께 확인할 수 있다.

**요구사항**

| ID | 내용 |
|----|------|
| F-02-1 | 상품 ID로 특정 상품의 상세 정보를 조회할 수 있다. |
| F-02-2 | 존재하지 않거나 판매 중단된 상품을 조회하면 "찾을 수 없음" 오류를 반환한다. |
| F-02-3 | 로그인한 고객은 해당 상품에 본인이 좋아요를 눌렀는지 여부를 함께 확인할 수 있다. 로그인하지 않은 경우 해당 항목은 제공되지 않는다. |

**상세 페이지에서 확인할 수 있는 정보**: 상품명, 상세 설명, 가격, 재고 수량, 브랜드 정보, 카테고리 정보, 좋아요 수, (로그인 시) 내 좋아요 여부

---

### F-03. 브랜드 조회

**시나리오**
> 고객이 특정 브랜드 페이지에 진입하거나, 상품 필터에서 브랜드를 선택하기 위해 브랜드 목록을 조회한다.

**요구사항**

| ID | 내용 |
|----|------|
| F-03-1 | 전체 브랜드 목록을 조회할 수 있다. |
| F-03-2 | 브랜드 ID로 특정 브랜드의 상세 정보를 조회할 수 있다. |
| F-03-3 | 존재하지 않는 브랜드를 조회하면 "찾을 수 없음" 오류를 반환한다. |

**브랜드 정보**: 브랜드명, 설명

---

### F-04. 상품 좋아요 등록

**시나리오**
> 로그인한 고객이 마음에 드는 상품에 좋아요를 누른다. 이미 좋아요를 누른 상품이라도 오류 없이 정상 처리된다.

**요구사항**

| ID | 내용 |
|----|------|
| F-04-1 | 로그인한 고객은 상품에 좋아요를 등록할 수 있다. |
| F-04-2 | 이미 좋아요를 누른 상품에 다시 요청해도 오류 없이 정상 처리된다. |
| F-04-3 | 로그인하지 않은 상태에서 좋아요를 요청하면 인증 오류를 반환한다. |
| F-04-4 | 존재하지 않거나 판매 중단된 상품에 좋아요를 요청하면 "찾을 수 없음" 오류를 반환한다. |

---

### F-05. 상품 좋아요 취소

**시나리오**
> 로그인한 고객이 이전에 누른 좋아요를 취소한다. 이미 취소된 상태에서 다시 취소 요청을 해도 오류가 없어야 한다.

**요구사항**

| ID | 내용 |
|----|------|
| F-05-1 | 로그인한 고객은 본인이 누른 좋아요를 취소할 수 있다. |
| F-05-2 | 이미 취소된 상품에 다시 취소 요청해도 오류 없이 정상 처리된다. |
| F-05-3 | 로그인하지 않은 상태에서 취소를 요청하면 인증 오류를 반환한다. |
| F-05-4 | 다른 고객의 좋아요는 취소할 수 없다. |

---

### F-06. 주문 생성

**시나리오**
> 로그인한 고객이 1개 이상의 상품을 선택하고 수량을 지정해 주문을 넣는다. 재고가 부족하거나 포인트가 모자라면 주문이 접수되지 않는다.

**요구사항**

| ID | 내용 |
|----|------|
| F-06-1 | 로그인한 고객은 상품과 수량을 지정해 주문을 생성할 수 있다. 상품은 1개 이상이어야 한다. |
| F-06-2 | 주문에 포함된 상품 중 하나라도 존재하지 않거나 판매 중단된 경우 주문이 생성되지 않는다. |
| F-06-3 | 주문 수량이 현재 재고를 초과하면 주문이 생성되지 않는다. |
| F-06-4 | 포인트로 결제할 경우, 보유 포인트가 주문 금액보다 부족하면 주문이 생성되지 않는다. |
| F-06-5 | 주문이 정상 접수되면 결제 대기 상태로 생성되며, 생성 시점부터 30분 동안 유효하다. |
| F-06-6 | 로그인하지 않은 상태에서 주문을 요청하면 인증 오류를 반환한다. |
| F-06-7 | 결제 대기 상태로 30분이 경과한 주문은 자동으로 취소되며 취소 사유로 "만료"가 기록된다. |

**주문 상태 흐름**

```
결제 대기 → 결제 완료 → 처리 완료
               ↘ 취소됨
```

| 상태 | 설명 |
|------|------|
| 결제 대기 | 주문이 접수되어 결제를 기다리는 상태 (30분 유효) |
| 결제 완료 | 결제가 정상 처리된 상태 |
| 처리 완료 | 배송 등 이후 처리까지 완료된 상태 |
| 취소됨 | 결제 실패 / 사용자 취소 / 만료로 인해 취소된 상태 (사유는 별도 기록) |

---

### F-07. 결제 처리

**시나리오**
> 고객이 주문 접수 후 결제를 진행한다. 포인트 차감, 재고 차감, 외부 결제 순으로 처리되며, 중간에 하나라도 실패하면 이미 처리된 항목을 모두 원래대로 되돌린다.

**요구사항**

| ID | 내용 |
|----|------|
| F-07-1 | 결제 대기 상태이며 만료되지 않은 주문에 대해서만 결제를 진행할 수 있다. |
| F-07-2 | 결제 수단은 포인트 또는 외부 결제 중 하나를 선택한다. 혼합 결제는 지원하지 않는다. |
| F-07-3 | 포인트 결제 시 보유 포인트가 주문 금액 이상이어야 한다. |
| F-07-4 | 재고는 결제가 완료되는 시점에 차감된다. |
| F-07-5 | 결제 도중 어느 단계에서든 실패가 발생하면 차감된 포인트와 재고를 모두 원상복구하고 주문을 취소 처리한다. |
| F-07-6 | 결제가 완료되면 주문 상태가 결제 완료로 변경된다. |
| F-07-7 | 본인의 주문이 아닌 결제 요청은 거부한다. |
| F-07-8 | 동일한 결제 요청이 중복으로 전달되는 경우(따닥 클릭, 네트워크 재전송 등) 한 번만 처리되며 동일한 응답을 반환한다. |

**결제 처리 순서**

```
① 포인트 차감  →  ② 재고 차감  →  ③ 외부 결제 요청  →  ④ 주문 상태 변경 (결제 완료)
```

실패 발생 시 해당 단계 이전에 처리된 항목을 역순으로 원상복구한다.

## 비기능 요구사항

| 항목 | 내용 |
|------|------|
| 인증 | 좋아요·주문·결제 기능은 로그인한 회원만 사용할 수 있다. |
| 멱등성 (좋아요) | 좋아요 등록과 취소는 동일한 요청을 여러 번 해도 결과가 달라지지 않는다. |
| 멱등성 (결제) | 결제 요청은 클라이언트가 발급한 멱등성 키(`Idempotency-Key`)를 통해 중복 처리가 차단된다. 동일 키로 재전송 시 이전 응답이 그대로 반환된다. |
| 데이터 일관성 | 결제 흐름에서 포인트·재고·주문 상태는 항상 일치된 상태를 유지해야 한다. |
| 삭제 정책 | 상품과 브랜드는 삭제해도 데이터가 보존된다. 좋아요는 취소 시 완전히 삭제된다. |
