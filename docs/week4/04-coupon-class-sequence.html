CLASS · 1

할인 정책 (단일 object)

할인 계산은 단일 object DiscountPolicy 가 type 분기 + 캡(할인 ≤ 주문금액)까지 담당합니다. 사용 자격(minOrder·만료) 검증은 Coupon.validateUsable 이 따로 — 계산과 검증을 분리합니다.

DiscountPolicy.kt
object DiscountPolicy {
    fun calculateDiscount(type: CouponType, value: Long, price: Money): Money {
        val raw = when (type) {
            FIXED -> value
            RATE  -> price.amount * value / 100
        }
        return Money(minOf(raw, price.amount))   // 캡: 할인 ≤ 주문금액
    }
}
2

CLASS · 2

쿠폰 엔티티 관계

Coupon(템플릿)과 UserCoupon(보유)을 분리하고, 각각 enum을 필드로 참조합니다.

왜 ID 참조인가주문 스냅샷(OrderItem)이 productId 를 ID 로 들고 있는 컨벤션과 동일합니다. 애그리거트 경계를 넘는 직접 객체 참조 대신 ID 로 느슨하게 연결합니다.
3

SEQUENCE · 1

발행 · 지급 시퀀스

관리자가 쿠폰을 발행(템플릿 생성)하고, 특정 사용자에게 지급(UserCoupon 생성)하는 흐름. 관리자 단독 행위라 선착순 경합이 없습니다.

4

SEQUENCE · 2

사용 · 주문 시퀀스

주문 시 쿠폰을 적용하는 흐름. 한 트랜잭션 안에서 재고 차감 → 할인 계산 → 쿠폰 사용 → 주문 저장.

검증과 계산의 분리Coupon.validateUsable(amount, now) 가 minOrder·만료를 검증하고, 계산+캡은 DiscountPolicy.calculateDiscount(type, value, amount) 가 담당합니다. 둘을 OrderService 가 순서대로 호출 — Coupon 은 DiscountPolicy 를 의존하지 않습니다.
5

USER FLOW

유저 플로우

사용자 입장에서 쿠폰은 네 단계로 흐릅니다 — 관리자에게 받고, 확인하고, 주문에 적용하고, 할인된 금액을 결제합니다.

단계사용자 행동API
① 수령관리자가 지급 → 내 보유함에(관리자) POST /api-admin/v1/coupons/{id}/grant
② 조회쓸 수 있는 쿠폰 확인GET /users/me/coupons
③ 적용주문에 쿠폰 1장 얹기POST /orders (couponId)
④ 결제할인된 금액 확인·결제(주문 응답의 최종 금액)
