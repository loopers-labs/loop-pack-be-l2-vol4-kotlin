01

OVERVIEW

개요

관리자가 쿠폰 정책을 생성하는 관리용 엔드포인트입니다.

이 API 는 실제 사용자에게 쿠폰을 지급하지 않습니다. 발급 가능한 쿠폰의 정의(템플릿)를 만들 뿐입니다. 여기서 만든 쿠폰을 개별 사용자에게 지급하는 작업은 별도의 POST /api-admin/v1/coupons/{couponId}/grant (쿠폰 발급) 에서 처리합니다.

핵심경로 프리픽스 /api-admin 은 일반 사용자용 /api/v1 과 구분되는 관리용 영역입니다. 보안 설정에서 /api-admin/v1/** 전 경로가 인증을 요구하며, 별도의 관리자 인증 필터가 앞단에 붙어 ADMIN 권한을 검증합니다 (4번 섹션 참조).

생성되는 쿠폰은 두 가지 할인 타입을 가질 수 있습니다 — 정액(FIXED) 과 정률(RATE). 할인 값(value)의 의미와 검증 규칙은 타입에 따라 달라지며, 자세한 내용은 다음 섹션에서 다룹니다.

02

REQUEST & RESPONSE

요청 · 응답

엔드포인트 시그니처

CouponController.kt 
// 요청 본문 + 인증 attribute(ACCOUNT_ID) 를 받아 생성 커맨드로 변환
@PostMapping("/api-admin/v1/coupons")
fun createCoupon(
    @RequestBody couponCreateRequest: CouponCreateRequest,
    @RequestAttribute(ACCOUNT_ID) requestAccountId: Long,
) = couponService.create(couponCreateRequest.toCommand(requestAccountId))

요청 본문 — CouponCreateRequest

필드타입설명
couponNameString쿠폰 이름. 엔티티 name 으로 저장 (생성 후 변경 불가)
expiredAtLocalDateTime쿠폰 만료 일시. 현재 시각 이후여야 함
couponTypeCouponType할인 타입 enum — FIXED 또는 RATE
valueLong할인 값. 타입별 의미가 다름 (아래 표 참조). 0보다 커야 함
minOrderAmountLong최소 주문 금액. 엔티티에서 Money VO 로 래핑 저장. 쿠폰 사용 시 이 금액 이상이어야 적용

CouponType — 할인 타입

도메인 enum CouponType 은 두 값만 정의되어 있습니다. value 의 해석과 검증 규칙이 타입에 따라 달라집니다.

값의미value 해석 · 검증
FIXED정액 할인value 원만큼 할인. value > 0 이면 충분
RATE정률 할인value % 할인. 0 < value <= 100 범위여야 함
참고할인 금액 계산(DiscountPolicy.calculateDiscount)은 이 생성 API 가 아니라 쿠폰 사용 시점에 일어납니다. 정률은 주문금액 × value / 100, 정액은 value 이며, 어느 쪽이든 주문 금액을 넘지 않도록 캡(cap)이 걸립니다.

응답

서비스의 create 는 반환값이 없습니다(Unit). 컨트롤러도 별도 payload DTO 를 만들지 않고, 공통 ResponseBodyAdvice 가 성공 응답을 ApiResponse 로 래핑합니다. 프로젝트 규약상 payload 가 없을 때는 placeholder DTO 를 만들지 않으므로 data 는 비어 있습니다 (Jackson NON_NULL 정책으로 생략 가능).

필드타입설명
meta.resultString성공 시 SUCCESS
meta.errorCodeString?성공 시 null (생략)
meta.messageString?성공 시 null (생략)
data—본문 없음. 생성된 식별자도 반환하지 않음
response.json 
{
  "meta": { "result": "SUCCESS" }
}
03

SEQUENCE

시퀀스 다이어그램

관리자 요청이 컨트롤러 → 애플리케이션 → 도메인 → 리포지토리를 거쳐 DB 에 저장되기까지의 흐름입니다. 만료일 검증은 애플리케이션에서, 할인 값 검증은 도메인(Coupon init) 에서 일어납니다. 점선 박스는 @Transactional 경계입니다.

04

BUSINESS LOGIC

비즈니스 로직

검증은 두 레이어로 나뉩니다 — 만료일은 애플리케이션, 할인 값은 도메인.

① 만료일 검증 (애플리케이션)

CouponService.create 가 가장 먼저 만료일을 검사합니다. 만료일이 현재 시각보다 과거이면 생성을 거부합니다.

CouponService.kt 
@Transactional
fun create(couponCreateCommand: CouponCreateCommand) {
    if (couponCreateCommand.expiredAt < LocalDateTime.now()) {
        throw BadRequestException(CouponErrorCode.EXPIRED_AT_IN_PAST)
    }
    val coupon = Coupon(
        type = couponCreateCommand.couponType,
        name = couponCreateCommand.couponName,
        value = couponCreateCommand.value,
        minOrderAmount = Money(couponCreateCommand.minOrderAmount),
        expiredAt = couponCreateCommand.expiredAt,
        createdBy = couponCreateCommand.requestAccountId,
    )
    couponRepository.save(coupon)
}

② 할인 값 검증 (도메인 init)

할인 값 검증은 Coupon 엔티티 생성자의 init 블록에 fail-fast 로 들어 있습니다 — 잘못된 값이 DB 까지 내려가 500 으로 떨어지지 않도록 도메인 invariant 로 강제합니다.

Coupon.kt 
init {
    if (value <= 0) {
        throw BadRequestException(CouponErrorCode.INVALID_DISCOUNT_VALUE)
    }
    if (type == CouponType.RATE && value > 100) {
        throw BadRequestException(CouponErrorCode.RATE_DISCOUNT_OUT_OF_RANGE)
    }
}
  • value > 0 — 모든 타입 공통. 0 이하면 INVALID_DISCOUNT_VALUE
  • RATE 이면 value ≤ 100 — 정률은 100% 초과 불가. 위반 시 RATE_DISCOUNT_OUT_OF_RANGE
  • FIXED 상한 없음 — 정액은 value > 0 만 검사 (사용 시점 캡으로 주문금액 초과 방지)

③ 저장 · 트랜잭션

검증을 통과하면 couponRepository.save(coupon) 로 영속화합니다. 메서드 전체가 @Transactional 경계 안에 있어, 검증 실패 시 예외가 던져져 트랜잭션이 롤백됩니다 (저장 전 단계라 실제 커밋되는 변경은 없습니다).

④ 예외 — 에러 코드

비즈니스 실패는 CoreException 서브클래스로 던져지고 ApiControllerAdvice 가 HTTP 상태로 매핑합니다. 이 생성 API 에서 직접 발생할 수 있는 에러 코드는 다음과 같습니다.

code발생 조건예외 · 상태
COUPON:EXPIRED_AT_IN_PAST만료일이 현재 시각보다 과거BadRequestException · 400
COUPON:INVALID_DISCOUNT_VALUE할인 값이 0 이하BadRequestException · 400
COUPON:RATE_DISCOUNT_OUT_OF_RANGERATE 인데 value > 100BadRequestException · 400
참고CouponErrorCode 에는 COUPON_NOT_FOUND · ALREADY_GRANTED · MIN_ORDER_NOT_MET · EXPIRED · ALREADY_USED 도 정의되어 있으나, 이들은 발급/사용 시점의 코드이며 생성 API 와는 무관합니다.

⑤ 관리자 인가 — 주의

주의 · 인가컨트롤러는 @RequestAttribute(ACCOUNT_ID) 만 받지만, 인가는 컨트롤러가 아니라 SecurityFilterChain + AdminLdapAuthenticationFilter 에서 처리됩니다. /api-admin/v1/** 은 authenticated() 로 보호되고, AdminLdapAuthenticationFilter 가 ① X-Loopers-Ldap: loopers.admin 헤더 ② X-Loopers-LoginId/X-Loopers-LoginPw 자격 증명 ③ 인증된 계정의 role == ADMIN 을 모두 검증합니다. 하나라도 실패하면 401 Unauthorized. 즉 단순 인증만이 아니라 관리자 권한까지 실제로 검사합니다.
주의 · 값 검증정액(FIXED)에는 상한 검증이 없습니다. value > 0 만 보장되므로, 비정상적으로 큰 정액 쿠폰도 생성 자체는 성공합니다. 실제 과다 할인은 사용 시점의 DiscountPolicy 캡(할인 ≤ 주문 금액)으로만 방어됩니다. 정률(RATE)만 생성 단계에서 1~100 범위로 제한됩니다.
