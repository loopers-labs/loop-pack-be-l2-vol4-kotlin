# Acceptance Test 시나리오

이 문서는 `docs/HLD.md`를 기준으로 시스템 전체 무결성을 확인하기 위한 E2E acceptance test 후보를 정의한다.
아직 테스트 코드는 작성하지 않고, 실제 테스트 구현 시 검증해야 할 사용자 여정과 결과만 기록한다.

## 목표

- 카탈로그, 좋아요, 주문, 결제 흐름이 사용자 관점에서 끊기지 않는지 확인한다.
- bounded context 경계를 넘는 흐름에서 재고, 주문 상태, 결제 결과, 주문 스냅샷이 일관되게 유지되는지 확인한다.
- 단순 CRUD나 API 세부 검증보다 핵심 비즈니스 불변식이 깨지지 않는지 확인한다.

## 작성 원칙

- E2E acceptance test는 적은 수의 핵심 여정만 다룬다.
- 각 시나리오는 사용자가 관찰할 수 있는 결과와 도메인 상태의 무결성을 함께 확인한다.
- 외부 결제 시스템은 실제 연동 대신 성공, 중복 성공, 취소 성공 같은 결과를 제어할 수 있는 대역으로 둔다.
- API 필드 단위 validation은 이 문서의 범위에서 제외한다.

## 공통 전제

- 쇼핑몰 관리자와 쇼핑몰 소비자가 존재한다고 가정한다.
- 상품 재고는 카탈로그 context가 관리한다.
- 쇼핑카트는 주문 context에 속하며, 재고를 예약하지 않는다.
- 주문 상태는 `결제대기`, `주문완료`, `주문취소`, `배송시작`을 사용한다.
- 주문 스냅샷은 주문 시점의 상품 ID, 상품명, 브랜드명, 판매가, 주문 수량을 보존한다.

## 시나리오 목록

### A-01. 상품 등록 후 소비자가 상품과 브랜드를 조회할 수 있다

**Given**

- 관리자가 브랜드를 등록한다.
- 관리자가 해당 브랜드의 여러 상품을 가격, 상세 정보, 재고와 함께 등록한다.
- 각 상품의 좋아요 수가 서로 다르게 집계되어 있다.

**When**

- 소비자가 `latest`, `price_asc`, `likes_desc` 정렬 조건으로 상품 목록을 조회한다.
- 소비자가 상품 상세를 조회한다.
- 소비자가 브랜드를 조회한다.

**Then**

- 상품 목록과 브랜드 조회 결과에서 등록된 상품을 확인할 수 있다.
- `latest` 상품 목록은 상품 등록일자 역순 기준으로 조회된다.
- `price_asc` 상품 목록은 가격 오름차순 기준으로 조회된다.
- `likes_desc` 상품 목록은 좋아요 수 내림차순 기준으로 조회된다.
- 상품 목록과 상품 상세에는 상품 정보, 브랜드 정보, 좋아요 수가 함께 제공된다.
- 상품 상세에서는 상품 정보와 상세 설명 이미지를 확인할 수 있다.
- 상품 등록과 조회만으로 재고 수량은 변하지 않는다.

### A-02. 좋아요 등록과 취소는 멱등하게 반영된다

**Given**

- 소비자가 좋아요를 누르지 않은 상품이 존재한다.

**When**

- 소비자가 같은 상품에 좋아요 등록을 여러 번 요청한다.

**Then**

- 소비자의 좋아요 상태는 등록 상태가 된다.
- 좋아요 원장에는 소비자의 최종 선호 상태가 일관되게 남는다.
- 상품의 좋아요 집계는 한 번만 증가한다.
- 상품 목록이나 상세 조회에서 소비자가 좋아요 한 상품임을 확인할 수 있다.

**When**

- 소비자가 같은 상품에 좋아요 취소를 여러 번 요청한다.

**Then**

- 소비자의 좋아요 상태는 취소 상태가 된다.
- 상품의 좋아요 집계는 한 번만 감소한다.
- 상품 목록이나 상세 조회에서 소비자가 좋아요 하지 않은 상품임을 확인할 수 있다.

### A-03. 쇼핑카트 담기는 재고를 확인하지만 예약하지 않는다

**Given**

- 재고가 1개인 상품이 존재한다.

**When**

- 소비자 A가 해당 상품 1개를 쇼핑카트에 담는다.

**Then**

- 쇼핑카트 담기는 성공한다.
- 상품 재고는 예약되거나 차감되지 않는다.

**When**

- 소비자 B가 같은 상품 1개로 주문창에 접근한다.

**Then**

- 소비자 B의 재고 예약은 성공할 수 있다.
- 이후 소비자 A가 주문창에 접근하면 재고 예약 실패가 발생할 수 있다.
- 쇼핑카트는 구매 의도만 보관하며 재고 보장을 하지 않는다.

### A-04. 주문창 접근 시 결제대기 주문과 재고 예약이 함께 생성된다

**Given**

- 소비자의 쇼핑카트에 재고가 충분한 여러 상품과 각 주문 수량이 담겨 있다.

**When**

- 소비자가 주문창에 접근한다.

**Then**

- 결제대기 상태의 주문이 생성된다.
- 주문은 여러 주문 상품과 각 주문 수량을 포함한다.
- 주문 상품 수량만큼 재고가 예약된다.
- 주문창 접근은 모든 주문 상품의 재고 예약이 성공해야만 성공한다.
- 소비자는 배송 주소, 배송시 요청사항, 전화번호를 입력할 수 있다.
- 결제가 완료되기 전까지 계약이 체결된 주문으로 보지 않는다.

### A-05. 결제 완료는 재시도와 멱등 처리 후 주문완료로 수렴한다

**Given**

- 결제대기 주문이 존재하고, 주문 수량만큼 재고가 예약되어 있다.

**When**

- 외부 결제 시스템에서 결제 완료 결과가 전달된다.
- 같은 결제 완료 결과가 중복 전달되거나, 처리 중 실패 후 재시도된다.

**Then**

- 주문은 최종적으로 주문완료 상태가 된다.
- 예약된 재고는 한 번만 차감된다.
- 같은 주문에 대해 중복 주문완료나 중복 재고 차감이 발생하지 않는다.
- 결제가 완료된 주문은 재시도와 멱등 처리로 반드시 주문완료에 도달한다.

### A-06. 결제 전 주문 취소나 예약 만료는 예약 재고를 반환한다

**Given**

- 결제대기 주문이 존재하고, 주문 수량만큼 재고가 예약되어 있다.
- 아직 결제는 완료되지 않았다.

**When**

- 소비자가 주문을 취소한다.

**Then**

- 주문은 주문취소 상태가 된다.
- 예약된 재고는 예약 취소되어 다시 주문 가능해진다.
- 결제 취소 요청은 발생하지 않는다.

**When**

- 결제가 발생하지 않은 채 예약 유효 시간이 지난다.

**Then**

- 예약된 재고는 자동으로 예약 취소된다.
- 해당 재고는 다른 주문에서 다시 예약할 수 있다.

### A-07. 배송 시작 전 주문 취소는 재고 복구와 결제 취소를 함께 수행한다

**Given**

- 주문완료 상태의 주문이 존재한다.
- 아직 배송은 시작되지 않았다.

**When**

- 소비자가 주문을 취소한다.

**Then**

- 주문은 주문취소 상태가 된다.
- 차감된 재고는 복구된다.
- 결제 취소가 요청된다.
- 취소된 주문은 다시 주문완료 상태로 돌아가지 않는다.

### A-08. 배송 시작 후에는 주문을 취소할 수 없다

**Given**

- 주문완료 상태의 주문이 존재한다.

**When**

- 관리자가 배송 시작을 체크한다.

**Then**

- 주문은 배송시작 상태가 된다.
- 관리자는 주문 내역에서 배송 시작 상태를 확인할 수 있다.

**When**

- 소비자가 배송시작 상태의 주문을 취소하려고 한다.

**Then**

- 주문 취소는 거부된다.
- 주문 상태는 배송시작으로 유지된다.
- 재고 복구와 결제 취소는 발생하지 않는다.

### A-09. 주문 스냅샷은 상품이나 브랜드 변경과 무관하게 유지된다

**Given**

- 소비자가 상품을 주문완료 상태까지 진행했다.
- 주문에는 상품 ID, 상품명, 브랜드명, 판매가, 주문 수량 스냅샷이 저장되어 있다.

**When**

- 관리자가 주문 이후 상품명, 브랜드명, 가격, 상세 정보를 수정한다.

**Then**

- 소비자의 주문 조회 결과에는 주문 당시의 상품명, 브랜드명, 판매가, 주문 수량이 표시된다.
- 상품 조회 결과에는 수정된 최신 상품 정보가 표시된다.
- 주문 스냅샷은 상품이나 브랜드 변경으로 수정되지 않는다.

### A-10. 한정 재고 상품에 대해 동시에 주문해도 재고 무결성이 깨지지 않는다

**Given**

- 재고가 1개인 상품이 존재한다.
- 소비자 A와 소비자 B가 각각 해당 상품 1개를 쇼핑카트에 담았다.

**When**

- 두 소비자가 같은 시점에 주문창 접근을 시도한다.

**Then**

- 하나의 주문만 재고 예약에 성공한다.
- 다른 주문은 재고 부족으로 주문창 접근에 실패한다.
- 성공한 주문이 결제 완료되면 재고는 한 번만 차감된다.
- 실패한 주문으로 인해 음수 재고, 중복 예약, 중복 주문완료가 발생하지 않는다.
- 재고 차감은 재고 수량을 0 미만으로 만들 수 없다.

### A-11. 관리자 주문 내역은 소비자 주문 흐름과 일관된다

**Given**

- 여러 소비자가 상품을 주문하고 일부 주문은 주문완료, 일부 주문은 주문취소 상태가 되었다.

**When**

- 관리자가 상품의 주문 내역을 확인한다.

**Then**

- 관리자는 각 주문 요청의 현재 상태를 확인할 수 있다.
- 주문취소 상태의 주문은 취소 상태로 표시된다.
- 주문완료 상태의 주문은 배송 시작 체크가 가능하다.
- 관리자가 배송 시작을 체크한 주문은 소비자 주문 조회에서도 배송시작 상태로 표시된다.

### A-12. 존재하지 않는 주문 주체나 상품, 재고 부족은 주문을 만들지 않는다

**Given**

- 존재하지 않는 소비자 식별자로 주문창 접근을 시도할 수 있다.
- 존재하지 않는 상품 식별자나 재고가 부족한 상품이 쇼핑카트에 포함될 수 있다.

**When**

- 소비자가 주문창에 접근한다.

**Then**

- 주문창 접근은 실패한다.
- 결제대기 주문은 생성되지 않는다.
- 어떤 상품 재고도 예약되거나 차감되지 않는다.
- 이미 존재하던 쇼핑카트와 주문 데이터는 임의로 삭제되거나 변경되지 않는다.
