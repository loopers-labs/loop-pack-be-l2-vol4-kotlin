# 요구사항 정의서

## 1. 프로젝트 개요

- 목적: 감성 이커머스 플랫폼의 백엔드 시스템을 설계·구현한다. 좋아요, 쿠폰, 카드 결제 등 핵심 커머스 기능을 제공하고, 유저 행동 데이터를 기반으로 랭킹과 추천으로 연결되는 서비스를 구축한다.
- 배경: 좋아요 누르고, 쿠폰 쓰고, 카드로 결제하는 감성 이커머스. 내가 좋아하는 브랜드의 상품들을 한 번에 담아 주문하고, 유저 행동은 랭킹과 추천으로 연결된다.
- 도메인 범위
  - 회원(User): 서비스에 가입하여 인증/인가를 거쳐 상품 구매, 포인트 적립 등의 활동을 수행하는 주체. 비회원/회원/관리자 역할을 구분한다.
  - 상품(Product): 회원이 조회하고 구매할 수 있는 판매 단위. 이름, 가격, 설명 등의 속성을 가지며, 재고와 1:1, 브랜드와 N:1로 연관된다.
  - 브랜드(Brand): 상품을 제공하는 브랜드. 하나의 브랜드는 여러 상품을 보유하며, 회원은 브랜드 단위로 상품을 탐색할 수 있다.
  - 주문(Order): 회원이 상품을 구매하기 위해 생성하는 거래 단위. 주문 생성 → 결제 대기 → 결제 완료 → 배송 중 → 배송 완료 / 주문 취소 등의 상태를 가진다.
  - 결제(Pay): 주문에 대한 금액을 지불하는 행위. 결제 수단(카드, 계좌이체 등)을 통해 처리되며, 포인트 사용이 결제 금액에 반영된다.
  - 포인트(Point): 결제 완료 시 결제 금액의 1%가 적립되며, 다음 결제 시 현금 대신 사용할 수 있는 재화. 적립/사용/만료 내역을 관리한다.
  - 재고(Stock): 상품별 판매 가능 수량. 주문 생성 시 차감되고, 주문 취소 시 복원된다. 재고 부족 시 주문이 불가하다.

## 2. 설계 범위

### 포함 도메인
- 브랜드(Brand), 상품(Product), 재고(Stock), 좋아요(Like), 좋아요 수(LikeCount), 주문(Order), 결제(Pay), 포인트(Point)
- 유저(User): 이미 구현 완료 (회원가입, 내 정보 조회, 비밀번호 변경)

### 핵심 결정사항

| 항목 | 결정 |
|---|---|
| 삭제 정책 | 재고, 회원, 상품, 주문, 결제는 삭제해도 데이터 보존 / 좋아요, 좋아요 수, 브랜드는 완전 삭제 |
| 브랜드 삭제 | 연쇄 삭제 (상품 삭제 + 재고 삭제 + 좋아요 완전 삭제) |
| 좋아요 중복 방지 | 같은 회원이 같은 상품에 좋아요를 여러 번 보내도 1번만 등록된다. 이미 취소된 좋아요를 다시 취소해도 에러 없이 무시한다. |
| 포인트 차감 시점 | 주문 생성 시 (재고 차감과 함께) |
| 포인트 적립 시점 | 결제 완료 시 (1%) |
| 외부 결제 | 실제 PG 연동 전까지 항상 성공을 반환하는 가짜 결제 모듈로 구현 |
| 인증/인가 | 헤더 기반 식별만, 토큰 없음 |

|---|---|---|

## 4. 도메인 상세

> **시나리오 코드 안내**
> - **SC**: 유저/비회원 시나리오 (예: SC-BRAND-1)
> - **ASC**: 어드민 시나리오 (예: ASC-BRAND-1)
> - SC와 ASC의 번호는 각각 독립적으로 매겨지며, 같은 번호가 같은 기능을 의미하지는 않습니다.

### 브랜드(Brand)

**도메인 정보**
- 브랜드명 (필수, 유니크)
- 브랜드 설명
- 관계: 브랜드 1 : N 상품

**제약사항**
- 브랜드명은 중복될 수 없다.
- 브랜드 삭제 시 해당 브랜드의 상품, 재고, 좋아요, 좋아요 수가 연쇄 삭제된다.

**SC-BRAND-1: 브랜드 상세를 조회한다**
- 액터: 비회원, 회원
- 정상흐름: 브랜드 ID로 브랜드명, 설명을 조회한다.
- 응답 정보: 브랜드 ID, 브랜드명, 설명
- 예외/조건 분기:
  - 존재하지 않는 브랜드 ID → 404 Not Found
 없음

**ASC-BRAND-1: 브랜드 목록을 조회한다**
- 액터: 관리자
- 정상흐름: 등록된 브랜드 목록을 페이지네이션으로 조회한다.
- 응답 정보: 브랜드 ID, 브랜드명, 설명, 페이지 정보(page, size, totalElements, totalPages)
- 예외/조건 분기:
  - 조회 결과가 없는 경우 → 빈 목록 반환 (200)
 없음

**ASC-BRAND-2: 브랜드 상세를 조회한다**
- 액터: 관리자
- 정상흐름: 브랜드 ID로 브랜드 상세 정보를 조회한다.
- 응답 정보: 브랜드 ID, 브랜드명, 설명, 생성일시, 수정일시
- 예외/조건 분기:
  - 존재하지 않는 브랜드 ID → 404 Not Found
 없음

**ASC-BRAND-3: 브랜드를 등록한다**
- 액터: 관리자
- 정상흐름: 브랜드명, 설명을 입력하여 새 브랜드를 등록한다.
- 예외/조건 분기:
  - 이미 존재하는 브랜드명 → 409 Conflict
 없음

**ASC-BRAND-4: 브랜드 정보를 수정한다**
- 액터: 관리자
- 정상흐름: 브랜드 ID를 지정하여 브랜드명, 설명을 전체 수정한다.
- 예외/조건 분기:
  - 존재하지 않는 브랜드 ID → 404 Not Found
  - 수정하려는 브랜드명이 이미 존재 → 409 Conflict
 없음

**ASC-BRAND-5: 브랜드를 삭제한다**
- 액터: 관리자
- 정상흐름: 브랜드 ID를 지정하여 브랜드를 삭제한다.
- 예외/조건 분기:
  - 존재하지 않는 브랜드 ID → 404 Not Found
  - 해당 브랜드의 상품 중 미완료 주문이 존재하는 경우 → 409 Conflict
 해당 브랜드의 상품을 ASC-PRODUCT-5(상품 삭제)로 각각 삭제한다. 상품 삭제 시 재고, 좋아요, 좋아요 수가 연쇄 삭제된다.

### 상품(Product)

**도메인 정보**
- 상품명 (필수)
- 가격 (필수, 0 초과)
- 설명
- 브랜드 ID (필수, 등록 후 변경 불가)
- 관계: 상품 N : 1 브랜드, 상품 1 : 1 재고

**제약사항**
- 가격은 0보다 커야 한다.
- 상품의 브랜드는 등록 시 결정되며 이후 변경할 수 없다.
- 상품 등록 시 반드시 이미 존재하는 브랜드를 지정해야 한다.
- 미완료 주문이 존재하는 상품은 삭제할 수 없다.
- 상품 삭제 시 상품과 재고 데이터는 보존되며, 좋아요와 좋아요 수는 완전 삭제된다.

**SC-PRODUCT-1: 상품 목록을 조회한다**
- 액터: 비회원, 회원
- 정상흐름: 상품 목록을 페이지네이션으로 조회한다. brandId로 필터링, sort(latest/price_asc/likes_desc)로 정렬할 수 있다.
- 응답 정보: 상품 ID, 상품명, 가격, 브랜드명, 좋아요 수, 페이지 정보(page, size, totalElements, totalPages)
- 예외/조건 분기:
  - 조회 결과가 없는 경우 → 빈 목록 반환 (200)
 없음

**SC-PRODUCT-2: 상품 상세를 조회한다**
- 액터: 비회원, 회원
- 정상흐름: 상품 ID로 상세 정보를 조회한다.
- 응답 정보: 상품 ID, 상품명, 가격, 설명, 브랜드 ID, 브랜드명, 재고 수량, 좋아요 수
- 예외/조건 분기:
  - 존재하지 않는 상품 ID → 404 Not Found
  - 삭제된 상품 ID → 404 Not Found
 없음

**ASC-PRODUCT-1: 상품 목록을 조회한다**
- 액터: 관리자
- 정상흐름: 등록된 상품 목록을 페이지네이션으로 조회한다. brandId로 필터링할 수 있다.
- 응답 정보: 상품 ID, 상품명, 가격, 브랜드 ID, 브랜드명, 재고 수량, 페이지 정보(page, size, totalElements, totalPages)
- 예외/조건 분기:
  - 조회 결과가 없는 경우 → 빈 목록 반환 (200)
 없음

**ASC-PRODUCT-2: 상품 상세를 조회한다**
- 액터: 관리자
- 정상흐름: 상품 ID로 상세 정보를 조회한다.
- 응답 정보: 상품 ID, 상품명, 가격, 설명, 브랜드 ID, 브랜드명, 재고 수량, 좋아요 수, 생성일시, 수정일시
- 예외/조건 분기:
  - 존재하지 않는 상품 ID → 404 Not Found
 없음

**ASC-PRODUCT-3: 상품을 등록한다**
- 액터: 관리자
- 정상흐름: 상품명, 가격, 설명, 브랜드 ID, 초기 재고 수량을 입력하여 새 상품을 등록한다.
- 예외/조건 분기:
  - 존재하지 않는 브랜드 ID → 404 Not Found
 ASC-STOCK-1(재고 초기값 생성)

**ASC-PRODUCT-4: 상품 정보를 수정한다**
- 액터: 관리자
- 정상흐름: 상품 ID를 지정하여 상품명, 가격, 설명, 재고 수량을 전체 수정한다.
- 예외/조건 분기:
  - 존재하지 않는 상품 ID → 404 Not Found
  - 브랜드 ID 변경 시도 → 400 Bad Request (브랜드는 수정 불가)
 ASC-STOCK-2(재고 수량 변경). 브랜드는 수정할 수 없다.

**ASC-PRODUCT-5: 상품을 삭제한다**
- 액터: 관리자
- 정상흐름: 상품 ID를 지정하여 상품을 삭제한다.
- 예외/조건 분기:
  - 존재하지 않는 상품 ID → 404 Not Found
  - 이미 삭제된 상품 ID → 404 Not Found
  - 미완료 주문이 존재하는 상품 → 409 Conflict
 ASC-STOCK-3(재고 삭제), SC-LIKE-4(해당 상품 좋아요 전체 삭제 → SC-LIKECOUNT-3 연쇄). 재고 삭제 실패 시 전체 롤백, 좋아요 삭제 실패 시 재고 삭제 롤백 후 전체 실패 처리.

### 재고(Stock)

**도메인 정보**
- 수량 (0 이상)
- 상품 ID (필수)
- 관계: 재고 1 : 1 상품

**제약사항**
- 수량은 0 미만이 될 수 없다.
- 상품 등록 시 함께 생성되며, 상품 삭제 시 함께 삭제된다.
- 주문 생성 시 차감되고, 주문 취소/결제 실패 시 복원된다.

**SC-STOCK-1: 재고를 N만큼 차감한다**
- 액터: 회원
- 정상흐름: 주문 생성 시 현재 수량에서 N만큼 차감한다.
- 예외/조건 분기:
  - 현재 수량 < N (재고 부족) → 400 Bad Request
 없음

**SC-STOCK-2: 재고를 N만큼 복원한다**
- 액터: 회원
- 정상흐름: 결제 실패 또는 주문 취소 시 차감했던 수량 N만큼 재고를 복원한다.
- 예외/조건 분기: 없음
 없음

**ASC-STOCK-1: 재고를 초기값으로 생성한다**
- 액터: 관리자
- 정상흐름: 상품 등록 시 입력된 초기 재고 수량으로 재고를 생성한다.
- 예외/조건 분기: 없음
 없음

**ASC-STOCK-2: 재고를 N으로 변경한다**
- 액터: 관리자
- 정상흐름: 상품 수정 시 입력된 수량 N으로 재고를 덮어쓴다.
- 예외/조건 분기: 없음
 없음

**ASC-STOCK-3: 재고를 삭제한다**
- 액터: 관리자
- 정상흐름: 상품 삭제 시 연관된 재고를 함께 삭제한다.
- 예외/조건 분기: 없음
 없음

### 좋아요(Like)

**도메인 정보**
- 회원 ID (필수)
- 상품 ID (필수)
- 관계: 회원 N : M 상품 (좋아요를 통한 다대다)

**제약사항**
- 동일 회원이 동일 상품에 좋아요는 하나만 존재한다.
- 같은 회원이 같은 상품에 좋아요를 여러 번 등록해도 1번만 등록된다. 이미 취소된 좋아요를 다시 취소해도 에러 없이 무시한다.
- 상품 삭제 시 해당 상품의 좋아요 데이터도 연쇄 삭제된다.
- 브랜드 삭제 시 해당 브랜드의 상품들에 대한 좋아요 데이터도 연쇄 삭제된다.

---

**SC-LIKE-1: 상품에 좋아요를 등록한다**
- 액터: 회원
- 정상흐름: 로그인한 회원이 상품에 좋아요를 등록한다.
  1. 해당 회원이 해당 상품에 이미 좋아요를 등록했는지 확인한다.
  2. 이미 좋아요가 존재하면 → 200 OK 반환 (무시). 후속 동작 없음.
  3. 좋아요가 존재하지 않으면 → 좋아요를 등록하고 SC-LIKECOUNT-1(좋아요 수 +1)을 수행한다.
- 예외/조건 분기:
  - 존재하지 않는 상품 ID → 404 Not Found
  - 삭제된 상품 ID → 404 Not Found
 좋아요가 새로 등록된 경우에만 SC-LIKECOUNT-1(좋아요 수 +1)

**SC-LIKE-2: 상품 좋아요를 취소한다**
- 액터: 회원
- 정상흐름: 로그인한 회원이 상품 좋아요를 취소한다.
  1. 해당 회원이 해당 상품에 좋아요를 등록했는지 확인한다.
  2. 좋아요가 존재하지 않으면 → 200 OK 반환 (무시). 후속 동작 없음.
  3. 좋아요가 존재하면 → 좋아요를 삭제하고 SC-LIKECOUNT-2(좋아요 수 -1)을 수행한다.
- 예외/조건 분기:
  - 존재하지 않는 상품 ID → 404 Not Found
  - 삭제된 상품 ID → 404 Not Found
 좋아요가 실제로 삭제된 경우에만 SC-LIKECOUNT-2(좋아요 수 -1)

**SC-LIKE-4: 상품의 좋아요를 전체 삭제한다**
- 액터: 회원 (상품 삭제 시 내부 호출)
- 정상흐름: 상품 삭제(ASC-PRODUCT-5) 후속으로, 해당 상품에 등록된 모든 좋아요를 삭제한다.
- 예외/조건 분기: 없음
 SC-LIKECOUNT-3(해당 상품의 좋아요 수 삭제)

**SC-LIKE-3: 좋아요한 상품 목록을 조회한다**

- 정상흐름: 로그인한 회원이 자신이 좋아요한 상품 목록을 조회한다.
- 응답 정보: 상품 ID, 상품명, 가격, 브랜드명
- 예외/조건 분기:
  - 본인이 아닌 userId로 접근 → 403 Forbidden
  - 존재하지 않는 userId → 404 Not Found
  - 좋아요한 상품이 없는 경우 → 빈 목록 반환 (200)

### 주문(Order)

**도메인 정보**
- 주문 ID
- 회원 ID (필수)
- 주문 상태 (CREATED / PAYMENT_PENDING / PAYMENT_COMPLETED / SHIPPING / DELIVERED / CANCELLED)
- 총 주문 금액
- 사용 포인트
- 주문일시
- 주문 항목 목록 (OrderItem)
  - 상품 ID
  - 수량
  - 주문 시점 상품 정보: 주문 시점의 상품명, 가격, 브랜드명 (이후 원본이 변경되어도 주문 내역은 유지)
- 관계: 주문 N : 1 회원, 주문 1 : N 주문 항목

**제약사항**
- 주문은 삭제해도 데이터가 보존된다 (상태 변경으로 관리).
- 주문 항목은 최소 1개 이상이어야 한다.
- 각 항목의 수량은 1 이상이어야 한다.
- 주문 생성 시 주문 시점의 상품 정보(상품명, 가격, 브랜드명)를 별도로 저장한다 (이후 상품 정보가 변경되어도 주문 내역은 유지).
- 주문 생성 시 재고 차감 + 포인트 차감이 함께 수행된다.
- 복수 상품 주문 시, 일부 상품이라도 재고 부족이면 주문 전체가 실패한다 (부분 주문 불가).
- 총 주문 금액 = Σ(상품 가격 × 수량)
- 실 결제 금액 = 총 주문 금액 - 사용 포인트
- 포인트 적립은 실 결제 금액의 1% 기준이다.
- 주문 상태 흐름:
  ```mermaid
  stateDiagram-v2
      [*] --> CREATED
      CREATED --> PAYMENT_PENDING
      PAYMENT_PENDING --> PAYMENT_COMPLETED
      PAYMENT_PENDING --> CANCELLED
      PAYMENT_COMPLETED --> SHIPPING
      SHIPPING --> DELIVERED
      DELIVERED --> [*]
      CANCELLED --> [*]
  ```

**SC-ORDER-1: 주문을 생성한다**
- 액터: 회원
- 정상흐름: 회원이 상품 목록(productId, quantity)과 사용할 포인트를 입력하여 주문을 생성한다.
  1. 주문 항목의 상품 존재를 확인하고 정보를 조회한다 (상품명, 가격, 브랜드명). (→ SC-PRODUCT-2)
  2. 각 상품의 재고를 확인하고 차감한다. (→ SC-STOCK-1)
  3. 포인트를 차감한다 (사용 시). (→ SC-POINT-1)
  4. 주문을 생성한다. 1에서 조회한 주문 시점의 상품 정보를 별도로 저장한다.
  5. 주문 상태는 CREATED로 설정된다.
  6. 결제를 요청한다. 주문 상태를 PAYMENT_PENDING으로 변경한다. (→ SC-PAY-1)
  7. 결제 결과에 따라 분기한다.
     - 성공: 주문 상태를 PAYMENT_COMPLETED로 변경한다. 포인트를 적립한다. (→ SC-POINT-2)
     - 실패: 주문을 취소한다. (→ SC-ORDER-4)
- 예외/조건 분기:
  - 존재하지 않는 상품 ID → 404 Not Found
  - 삭제된 상품 ID → 404 Not Found
  - 재고 부족 (복수 상품 중 하나라도 부족 시 주문 전체 실패) → 400 Bad Request
  - 사용 포인트가 총 주문 금액을 초과 → 400 Bad Request
  - 보유 포인트 부족 → 400 Bad Request
  - 결제 실패 → SC-ORDER-4(주문 취소)로 분기
 SC-STOCK-1(재고 차감) → SC-POINT-1(포인트 차감) → SC-PAY-1(결제 요청) → 성공 시 SC-POINT-2(포인트 적립) / 실패 시 SC-ORDER-4(주문 취소)

**SC-ORDER-2: 주문 목록을 조회한다**
- 액터: 회원
- 정상흐름: startAt ~ endAt 기간과 page, size 파라미터로 자신의 주문 목록을 페이지네이션으로 조회한다. (page 기본값 0, size 기본값 20)
- 응답 정보: 주문 ID, 주문 상태, 총 주문 금액, 사용 포인트, 주문일시, 페이지 정보(page, size, totalElements, totalPages)
- 예외/조건 분기:
  - startAt이 endAt보다 이후인 경우 → 400 Bad Request
  - 조회 결과가 없는 경우 → 빈 목록 반환 (200)
 없음

**SC-ORDER-3: 주문 상세를 조회한다**
- 액터: 회원
- 정상흐름: 주문 ID로 주문 정보와 주문 항목(주문 시점 상품 정보 포함)을 조회한다.
- 응답 정보: 주문 ID, 주문 상태, 총 주문 금액, 사용 포인트, 실 결제 금액, 적립 포인트, 주문일시, 주문 항목 목록(상품 ID, 수량, 주문 시점 상품명, 주문 시점 가격, 주문 시점 브랜드명)
- 예외/조건 분기:
  - 존재하지 않는 주문 ID → 404 Not Found
  - 본인의 주문이 아닌 경우 → 403 Forbidden
 없음

**SC-ORDER-4: 주문을 취소한다 (결제 실패 시)**
- 액터: 회원
- 정상흐름: 결제 실패 시 주문을 취소한다.
  1. 주문 상태를 CANCELLED로 변경한다.
  2. 차감했던 재고를 복원한다. (→ SC-STOCK-2)
  3. 차감했던 포인트를 복원한다. (→ SC-POINT-3)
- 예외/조건 분기: 없음
 SC-STOCK-2(재고 복원) → SC-POINT-3(포인트 복원)

**ASC-ORDER-1: 주문 목록을 조회한다**
- 액터: 관리자
- 정상흐름: 전체 주문 목록을 페이지네이션으로 조회한다.
- 응답 정보: 주문 ID, 회원 ID, 로그인 ID, 주문 상태, 총 주문 금액, 주문일시, 페이지 정보(page, size, totalElements, totalPages)
- 예외/조건 분기:
  - 조회 결과가 없는 경우 → 빈 목록 반환 (200)
 없음

**ASC-ORDER-2: 주문 상세를 조회한다**
- 액터: 관리자
- 정상흐름: 주문 ID로 주문 정보와 주문 항목을 조회한다.
- 응답 정보: 주문 ID, 회원 ID, 로그인 ID, 주문 상태, 총 주문 금액, 사용 포인트, 실 결제 금액, 적립 포인트, 주문일시, 주문 항목 목록(상품 ID, 수량, 주문 시점 상품명, 주문 시점 가격, 주문 시점 브랜드명)
- 예외/조건 분기:
  - 존재하지 않는 주문 ID → 404 Not Found
 없음

### 결제(Pay)

**도메인 정보**
- 결제 ID
- 주문 ID (필수)
- 결제 금액
- 결제 상태 (READY / IN_PROGRESS / SUCCESS / FAIL)
- 결제일시
- 관계: 결제 1 : 1 주문

**제약사항**
- 결제는 삭제해도 데이터가 보존된다 (상태 변경으로 관리).
- CREATED 상태의 주문만 결제를 요청할 수 있다.
- 외부 결제 시스템은 PaymentGateway로 정의하고, 실제 PG 연동 전까지 항상 성공을 반환하는 가짜 결제 모듈로 구현한다.
- 결제 실패 시 재고와 포인트를 모두 복원해야 한다.

**SC-PAY-1: 결제를 요청한다 (SC-ORDER-1 후속)**
- 액터: 회원
- 정상흐름: 주문 생성 직후 자동으로 결제를 요청한다.
  1. 결제 상태를 READY로 생성한다.
  2. 결제 상태를 IN_PROGRESS로 변경한다.
  3. 외부 결제 시스템(PaymentGateway)에 결제를 요청한다.
  4. 결제 성공 시 결제 상태를 SUCCESS로 변경한다.
  5. 결제 결과(성공/실패)를 SC-ORDER-1에 반환한다.
- 예외/조건 분기:
  - 외부 결제 실패 → SC-PAY-2로 분기
 없음 (결과를 호출자에게 반환)

**SC-PAY-2: 외부 결제가 실패한다 (SC-PAY-1 예외)**
- 액터: 회원
- 정상흐름: 외부 결제 시스템이 실패를 반환한다.
  1. 결제 상태를 FAIL로 변경한다.
  2. 실패 결과를 SC-ORDER-1에 반환한다.
- 예외/조건 분기: 없음
 없음 (결과를 호출자에게 반환)

**외부 결제 시스템 인터페이스:**
```kotlin
interface PaymentGateway {
    fun requestPayment(orderId: Long, amount: Long): PaymentResult
}
```
- 실제 구현은 항상 성공을 반환하는 가짜 결제 모듈로 처리한다.
- 향후 실제 PG 연동 시 구현체를 교체한다.

### 포인트(Point)

**도메인 정보**
- 회원 ID (필수)
- 잔액 (0 이상)
- 관계: 포인트 1 : 1 회원

**제약사항**
- 잔액은 0 미만이 될 수 없다.
- 회원가입 시 잔액 0으로 초기화된다.
- 사용 시점: 주문 생성 시 (재고 차감과 함께)
- 적립 시점: 결제 완료 시 (결제 금액의 1%)
- 복원 시점: 결제 실패 또는 주문 취소 시

**SC-POINT-1: 주문 시 포인트를 사용한다**
- 액터: 회원
- 정상흐름: 주문 생성 시 요청된 포인트만큼 잔액에서 차감한다.
- 예외/조건 분기:
  - 보유 포인트 < 사용 포인트 → 400 Bad Request
 없음

**SC-POINT-2: 결제 완료 시 포인트가 적립된다**
- 액터: 회원
- 정상흐름: 결제가 완료되면 실 결제 금액의 1%가 포인트로 적립된다. 소수점 이하는 내림(floor) 처리한다.
- 예외/조건 분기: 없음
 없음

**SC-POINT-3: 결제 실패/주문 취소 시 포인트가 복원된다**
- 액터: 회원
- 정상흐름: 결제 실패 또는 주문 취소 시 사용했던 포인트를 복원한다.
- 예외/조건 분기: 없음
 없음
