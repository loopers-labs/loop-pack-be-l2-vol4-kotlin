01

OVERVIEW

개요

로그인한 사용자가 자신의 비밀번호를 변경합니다.

요청 본문으로 currentPassword 와 newPassword 를 받습니다. 서비스는 인증 식별자(loginId)로 자격 증명(AccountCredential)을 조회하고, 현재 비밀번호가 저장된 해시와 일치하는지 확인한 뒤, 새 비밀번호를 정책 검증하고 인코딩하여 교체합니다.

이 엔드포인트는 인증이 필요합니다. AccountHeaderAuthenticationFilter 가 요청 헤더 X-Loopers-LoginId / X-Loopers-LoginPw 로 사용자를 인증하고, 성공 시 요청 attribute loginId (LOGIN_ID) 를 주입합니다. 컨트롤러는 이 attribute 만 사용합니다.

핵심비밀번호 변경 자체에는 요청 body 의 currentPassword 를 별도로 검증합니다. 헤더 인증(필터)과는 독립적으로, 애플리케이션 레이어에서 다시 한 번 현재 비밀번호 일치를 확인합니다.

AccountController.kt 
// 인증 필터가 검증 후 loginId attribute(LOGIN_ID) 주입
@PutMapping("/password")
fun changePassword(
    @RequestAttribute(AccountAuthenticationAttributes.LOGIN_ID) loginId: String,
    @RequestBody request: AccountPasswordChangeRequest,
) {
    accountService.changePassword(request.toCommand(loginId))
}

04

BUSINESS LOGIC

비즈니스 로직

AccountService.changePassword 는 @Transactional 경계 안에서 동작합니다.

AccountService.kt 
@Transactional
fun changePassword(command: AccountPasswordChangeCommand) {
    val identifier = CredentialIdentifier(CredentialMethod.PASSWORD, command.loginId)
    val credential = accountCredentialRepository.findBy(CredentialMethod.PASSWORD, identifier)
        ?: throw UnauthorizedException()                 // 401

    if (!passwordEncryptor.matches(command.currentPassword, credential.secret.value)) {
        throw UnauthorizedException()                       // 401 현재 비번 불일치
    }
    if (command.currentPassword == command.newPassword) {
        throw BadRequestException(AccountErrorCode.INVALID_PASSWORD)  // 400
    }

    PasswordValidator.validate(command.newPassword, credential.account.birthDate)
    credential.changeSecret(CredentialSecret(passwordEncryptor.encode(command.newPassword)))
    accountCredentialRepository.save(credential)
}

단계별 흐름

1. 자격 증명 조회 → findBy(PASSWORD, identifier)I/O · 조회
입력loginId → CredentialIdentifier(PASSWORD, loginId)
실패없으면 UnauthorizedException() → 401
의미존재 여부를 노출하지 않기 위해 not found 도 401 로 통일
2. 현재 비밀번호 일치 검증 → matches(current, secret)검증
판정passwordEncryptor.matches(currentPassword, credential.secret.value)
실패불일치 시 UnauthorizedException() → 401
구현BCryptPasswordEncryptor → Spring BCryptPasswordEncoder
3. 동일 비밀번호 거부 → current == new검증
판정currentPassword 와 newPassword 가 같으면 거부
실패BadRequestException(INVALID_PASSWORD) → 400
코드ACCOUNT:INVALID_PASSWORD
4. 새 비밀번호 정책 검증 → PasswordValidator.validate(new, birthDate)검증
길이8~16자 (벗어나면 INVALID_PASSWORD)
문자정규식 ^[!-~]{8,16}$ — 공백·비ASCII 금지
생년월일비밀번호의 숫자에 YYYYMMDD 또는 YYMMDD 포함 시 거부
실패모두 BadRequestException(INVALID_PASSWORD) → 400
5. 인코딩 후 교체 · 저장 → changeSecret · save상태 변형 · I/O
인코딩passwordEncryptor.encode(newPassword) → BCrypt 해시
교체credential.changeSecret(CredentialSecret(해시))
저장accountCredentialRepository.save(credential)
트랜잭션 경계조회·검증·교체·저장 전체가 하나의 @Transactional 안에서 일어납니다. 검증 단계에서 예외가 던져지면 변경은 커밋되지 않습니다 (Fail Fast). 트랜잭션은 애플리케이션 서비스 레이어에서만 관리합니다.
05

CAUTION

주의 사항

비밀번호 평문 노출 금지비밀번호는 BCrypt 해시로만 저장됩니다 (passwordEncryptor.encode). 평문은 어디에도 영속화하지 않습니다.
secret 로깅 금지CredentialSecret.toString() 은 원문 대신 [PROTECTED] 를 반환합니다. 로그·예외 메시지에 secret 값이 직접 노출되지 않도록 한 장치이므로, 앱 코드에서 credential.secret.value 를 직접 로깅하지 않습니다.
존재 여부 노출 차단자격 증명이 없는 경우와 현재 비밀번호 불일치를 모두 401 로 통일합니다. 에러 코드/메시지로 계정 존재 여부를 추론할 수 없게 하기 위함입니다.
PII 미포함 에러도메인 예외는 errorCode 만 사용하고, 예외 메시지에 사용자 입력값(비밀번호·loginId 등)을 끼워넣지 않습니다. ApiControllerAdvice 가 e.message 를 로깅할 때 PII 가 남지 않도록 합니다.
