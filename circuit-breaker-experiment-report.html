PG Circuit Breaker Experiment Report

TL;DR: PG 실패가 누적되면 circuit breaker를 OPEN하여 이후 요청을 PG로 보내지 않고 즉시 UNKNOWN 복구 흐름으로 넘긴다.

실험 목적

PG 장애가 지속될 때 commerce-api가 매 요청마다 외부 시스템에 계속 연결을 시도하면 워커 스레드와 PG 양쪽에 부하가 누적된다. CircuitBreaker로 장애 구간의 추가 호출을 차단한다.

테스트 시나리오

PgSimulatorPaymentGatewayAdapterTest에서 테스트 전용 breaker 설정을 sliding window 2, minimum calls 2로 낮추고 PG stub은 계속 500을 반환한다. 두 번 실패한 뒤 세 번째 요청은 PG stub에 도달하지 않아야 한다.

결과

구분 정책 결과 해석
Before CircuitBreaker 없음 Red 테스트 실패. 세 번째 요청도 PG stub에 도달하여 요청 수가 3회가 됨. 지속 장애 중에도 외부 호출이 계속 발생한다.
After 운영 기본값: window 10, minimum calls 5, failure rate 50%, open wait 5s, half-open calls 2 Green 테스트 통과. OPEN 이후 추가 요청은 fast-fail되어 PG 요청 수가 2회로 유지됨. 장애 구간에서 PG와 API 스레드를 보호하고, 기존 UNKNOWN + 상태 재조회 흐름을 유지한다.

판단

CircuitBreaker는 Retry 바깥에 배치했다. 따라서 개별 재시도 attempt가 아니라, 재시도를 모두 소진한 하나의 사용자 요청 실패를 breaker 실패로 기록한다. 4xx 계열 클라이언트 오류는 breaker 실패율 계산에서 제외한다.
