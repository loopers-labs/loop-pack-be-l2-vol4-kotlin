1

OVERVIEW

개요

경로 변수 productId 로 활성 상품 하나를 조회해 상세 정보를 돌려줍니다.

상품의 식별자·이름·가격·좋아요 수에 더해, 해당 상품이 속한 브랜드의 brandName 을 함께 반환합니다. 브랜드명은 별도 컬럼이 아니라 BrandRepository 에서 따로 조회해 응답 시점에 결합합니다.

인증이 필요 없는 공개 엔드포인트입니다. AccountSecurityConfig 에서 GET /api/v1/products/* 경로를 permitAll() 로 열어 두었습니다.

핵심상품과 브랜드는 FK JOIN 이 아니라 각각 활성 상태로 단건 조회한 뒤 애플리케이션 레이어에서 결합합니다. 상품이 없으면 404 PRODUCT_NOT_FOUND, 브랜드가 없으면 404 BRAND_NOT_FOUND.

BUSINESS LOGIC

비즈니스 로직

ProductService.getDetail(id) 한 메서드에 조회·검증·결합이 모두 담겨 있습니다.

ProductService.kt 
@Transactional(readOnly = true)
fun getDetail(id: Long): ProductDetailInfo {
    val product = productRepository.findActiveById(id)
        ?: throw NotFoundException(ProductErrorCode.PRODUCT_NOT_FOUND)
    val brand = brandRepository.findActiveById(product.brandId)
        ?: throw NotFoundException(BrandErrorCode.BRAND_NOT_FOUND)
    return ProductDetailInfo.of(product, brand.name.value)
}

단계별 로직

STEP 1 · 상품 조회findActiveById(id) 로 활성 상품을 단건 조회합니다. 결과가 null 이면 NotFoundException(PRODUCT_NOT_FOUND) 를 던져 404 로 매핑됩니다.
STEP 2 · soft-delete 처리조회 메서드 이름이 findActiveById 인 데서 드러나듯, DELETED 상태 상품은 조회 대상에서 제외됩니다. ProductStatus 는 ACTIVE / DELETED 두 상태이며, soft delete 판단의 단일 출처는 deletedAt 이 아니라 status 입니다. 따라서 soft-delete 된 상품은 미존재와 동일하게 404 로 떨어집니다.
STEP 3 · brandName 결합상품의 brandId 로 BrandRepository.findActiveById 를 다시 호출해 브랜드를 조회합니다. FK JOIN 이 아니라 별도 단건 조회로 가져와 brand.name.value 를 ProductDetailInfo.of 에 전달해 결합합니다. 브랜드가 없거나 비활성이면 NotFoundException(BRAND_NOT_FOUND) → 404.
STEP 4 · 트랜잭션 경계메서드 전체가 @Transactional(readOnly = true) 로 묶여 있습니다. 쓰기 없는 조회 흐름이므로 읽기 전용 트랜잭션으로 dirty checking·flush 비용을 줄이고 의도를 명시합니다.
심화왜 JOIN 이 아니라 별도 조회인가

Product 엔티티는 brandId: Long 만 들고 있고 @ManyToOne 연관을 갖지 않습니다. 브랜드는 별도 bounded context 이므로 엔티티 연관 대신 식별자(brandId)만 참조하고, 상세 응답에 브랜드명이 필요할 때 BrandRepository 로 명시적으로 조회합니다.

두 조회 모두 활성 상태를 강제(findActiveById)하므로, 상품은 살아 있지만 브랜드가 삭제된 dangling 상태도 404 BRAND_NOT_FOUND 로 일관되게 차단됩니다. 단건 상세 조회라 단일 상품에 대한 추가 SELECT 1회뿐이며 N+1 문제는 발생하지 않습니다(목록 조회와 다른 경로).

주의상품이 존재해도 그 상품의 브랜드가 삭제(비활성)되었다면 응답은 200 이 아니라 404 BRAND_NOT_FOUND 입니다. 상세 응답은 brandName 을 필수 필드로 요구하므로, 브랜드명을 채울 수 없는 경우 상품을 노출하지 않습니다.
