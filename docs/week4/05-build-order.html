MAP

진행 순서 한눈에

안쪽(도메인)이 그린이면 바깥(서비스·API)에서 디버깅할 게 줄어듭니다. 그래서 A → H 순서입니다.

원칙① 각 커밋은 테스트가 초록일 때만 · ② 테스트 먼저, 구현 나중 · ③ 막히면 02·04 문서 펼치기.
2

DOMAIN

A~C · 순수 도메인

프레임워크 없이 코틀린만. 손이 풀리는 워밍업 구간입니다.

A. 할인 계산

  • CouponType enum — FIXED/RATE (표시명·분류 속성 없음, 식별만) feat
  • object DiscountPolicy.calculateDiscount(type, value, price) — when 분기 + 캡(min(raw, price)), 정률 내림 (테스트 먼저). 클래스·팩토리 없음 test

B. Coupon 템플릿 엔티티

  • CouponErrorCode — MIN_ORDER_NOT_MET · EXPIRED · ALREADY_USED feat
  • Coupon + validateUsable/isExpired(now) — name·createdBy, minOrderAmount:Money(@AttributeOverride). minOrder·만료 검증만(계산·캡은 DiscountPolicy), min 미달 예외 (테스트 먼저). @Enumerated(STRING) test

C. UserCoupon 보유 엔티티

  • UserCouponStatus enum — AVAILABLE/USED/EXPIRED feat
  • UserCoupon + use(now) — 전이 · 이미 USED/만료 예외 · @Version (테스트 먼저) test
3

OUTER

D~F · 영속 · 발급 · API

여기부터 DB·스프링 컨텍스트가 붙습니다. 통합 테스트(@DataJpaTest)와 E2E.

D. 영속 (port + adapter)

  • CouponRepository port + JPA adapter — findById. @DataJpaTest feat
  • UserCouponRepository port + adapter — save · findById · findAllByUserId feat

E. 관리자 발행 · 지급 유스케이스

  • CouponService.create — 관리자가 템플릿 발행(name·type·value·min·expiredAt·createdBy) test
  • CouponService.grant — 특정 userId 에게 UserCoupon(AVAILABLE) 지급, 템플릿 없으면 404 test
  • 중복 지급 방지 — UK(user_id, coupon_id) → Conflict feat

F. 관리자 발행·지급 · 내 조회 API

  • 관리자 발행 — POST /api-admin/v1/coupons (기존 admin 인증). 지급 .../{id}/grant. E2E feat
  • 내 쿠폰 조회 — GET /users/me/coupons (3상태), 사용자 인증. E2E feat
4

INTEGRATE

G~H · 주문 통합 · 동시성

쿠폰을 주문에 얹고, 마지막에 동시성으로 못을 박습니다.

G. 주문 통합

  • OrderCreateCommand.couponId + Order 금액 스냅샷 — originalAmount·discountAmount, create 시그니처 feat
  • place() 쿠폰 적용 — 재고 차감 뒤 조회·검증·calculateDiscount·use() (테스트) test
  • 실패 시 전체 롤백 — 쿠폰/재고 한쪽 실패 시 둘 다 원복 test

H. 동시성 (마지막)

  • 같은 쿠폰 동시 주문 1회만 — ExecutorService + CountDownLatch, Testcontainers MySQL test
  • 재고 · like_count — 이미 구현됨, 검증 테스트만 test
함정동시성 테스트는 H에서. A~G가 그린이 아닌 상태로 동시성부터 손대면 원인 분리가 안 됩니다.
5

TIPS

손코딩 팁

머리 푸는 중이라면, 이 세 가지만 지켜도 리듬이 잡힙니다.

1 · 작게커밋 하나에 한 가지. A의 1~5번은 DB·스프링 없이 순수 단위라 5분 안에 그린이 납니다. 거기서 리듬을 만드세요.
2 · 테스트 먼저test+feat 표시된 항목은 실패하는 테스트 → 통과시키는 구현 순. 무엇을 만들지 테스트가 먼저 정의합니다.
3 · 막히면 그림의존 방향이 헷갈리면 04 클래스 1·2, 주문 흐름이 헷갈리면 04 시퀀스 2, 락 판단은 03.
