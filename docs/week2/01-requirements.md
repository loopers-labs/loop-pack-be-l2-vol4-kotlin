# 01. 요구사항 명세

---

## 액터 정의

| 액터 | 설명 |
|------|------|
| **회원** | 서비스에 가입한 고객. 상품을 탐색하고 좋아요를 누르고 주문한다. |
| **비회원** | 로그인 없이 서비스를 이용하는 방문자. 상품·브랜드 조회만 가능하다. |
| **관리자** | 브랜드·상품·주문을 운영하는 내부 사용자. |

---

## 도메인 정의

| 도메인 | 설명 |
|--------|------|
| **브랜드** | 상품을 묶는 브랜드 단위. 관리자가 등록·수정·삭제하며, 삭제 시 소속 상품도 함께 삭제된다. |
| **상품** | 판매 가능한 아이템. 브랜드에 속하며 판매 상태와 판매 기간을 가진다. |
| **재고** | 상품의 판매 가능 수량. 주문 시 차감되고 주문 실패 시 복구된다. 재고가 0이면 품절로 표시된다. |
| **좋아요** | 회원이 관심 상품에 표시하는 기능. 같은 상품에 여러 번 눌러도 한 번만 등록된다. |
| **주문** | 회원의 구매 의사가 담긴 거래 단위. 주문 시점의 상품 정보를 그대로 보존한다. |
| **결제** | 주문에 대한 실제 금전 거래. 외부 결제 시스템과 연동한다. |

## 상품

### 상품 목록 조회
`GET /api/v1/products?brandId={brandId}&sort={sort}&page={page}&size={size}`

[유저 스토리]
- 사용자는 상품 목록을 조회할 수 있다.
- 정렬 기준은 최신순, 가격이 낮은 순, 좋아요 높은 순으로 정렬할 수 있다.
- 한 페이지에 20개의 상품을 볼 수 있다. (기본값으로 조정 가능)

[기능 흐름]

**전제 조건**
- 로그인 없이도 이용할 수 있다.

**기능 요구사항**
- Main Flow
    - 판매 중인 상품 목록을 보여준다.
- Alternate Flow
    - 특정 브랜드를 선택하면 해당 브랜드의 상품만 볼 수 있다.
    - 정렬 기준을 선택하면 해당 기준으로 정렬된 상품을 볼 수 있다.
    - 페이지 번호와 개수를 지정해 원하는 만큼 상품을 볼 수 있다.
- Exception Flow
    - 조건에 맞는 상품이 없으면 빈 목록을 보여준다.

[기능 흐름]
**전제 조건**
- 로그인 없이도 이용할 수 있다.

**기능 요구사항**

    - 상품 번호로 해당 상품의 상세 정보를 보여준다.
- Alternate Flow
    - 재고가 없는 상품은 "품절" 표시와 함께 보여준다.
- Exception Flow
    - 존재하지 않는 상품이면 찾을 수 없다는 안내를 보여준다.

### 상품 좋아요 등록/취소
`POST /api/v1/products/{productId}/likes` — 좋아요 등록
`DELETE /api/v1/products/{productId}/likes` — 좋아요 취소

[유저 스토리]
- 회원은 상품에 좋아요를 누를 수 있다.
- 이미 좋아요한 상품을 다시 눌러도 오류 없이 동작한다.

[기능 흐름]
**전제 조건**
- 로그인한 회원만 이용할 수 있다.

**기능 요구사항**
- Main Flow
    - 좋아요 등록: 선택한 상품에 좋아요를 등록한다.
    - 좋아요 취소: 선택한 상품의 좋아요를 취소한다.
- Alternate Flow
    - 이미 좋아요한 상품에 다시 등록을 요청해도 정상 처리된다. (중복 등록 방지)
    - 이미 취소한 상품에 다시 취소를 요청해도 정상 처리된다. (중복 취소 방지)
- 좋아요 취소 시 데이터가 완전히 삭제된다. (이력 보존 없음)
- Exception Flow
    - 존재하지 않는 상품이면 오류 메시지를 보여준다.
    - 로그인하지 않은 상태로 요청하면 로그인이 필요하다는 안내를 보여준다.

## 주문

### 주문 생성
`POST /api/v1/orders`

[유저 스토리]
- 로그인한 회원은 상품을 주문할 수 있다.
- 상품은 한 개 또는 여러 개를 한 번에 주문할 수 있다.
- 주문이 완료되면 재고가 차감된다.
- 주문 내역에는 주문 당시의 상품명, 가격, 브랜드명이 기록된다. (이후 상품 정보가 바뀌어도 주문 내역은 그대로 유지된다.)
- 주문은 아래 상태를 가진다.
    - **결제 대기** : 주문이 생성되어 결제를 기다리는 상태
    - **결제 완료** : 결제까지 정상 완료된 상태
    - **결제 실패** : 결제에 실패해 주문이 취소된 상태 (재고 자동 복구)

[기능 흐름]
**전제 조건**
- 로그인한 회원만 이용할 수 있다.

**기능 요구사항**
- Main Flow
    1. 주문 상품 전체 확인
        - 상품이 존재하는지 확인한다.
        - 상품이 판매 중인지 확인한다.
        - 재고가 충분한지 확인한다.
    2. 주문 생성 (주문 당시 상품명·가격·브랜드명 기록)
    3. 재고 차감
    4. 결제 진행 (외부 결제 시스템 연동)
    5. 주문 완료
- Alternate Flow
    - 동일한 결제 요청이 중복으로 들어올 경우, 이미 처리된 결과를 그대로 돌려준다. (이중 결제 방지)
- Exception Flow
    - 재고 부족: 재고가 부족한 상품이 있으면 주문 생성에 실패한다.
    - 재고 차감 실패: 주문이 몰려 차감 시점에 재고가 소진된 경우 주문에 실패한다.
    - 결제 실패: 결제에 실패하면 차감된 재고를 자동으로 복구하고 주문을 실패 처리한다.
    - 존재하지 않는 상품: 주문 목록에 존재하지 않는 상품이 있으면 주문 생성에 실패한다.
    - 로그인하지 않은 상태로 요청하면 로그인이 필요하다는 안내를 보여준다.

- Exception Flow
    - 존재하지 않는 상품이면 오류 메시지를 보여준다.
    - 관리자 권한이 없으면 접근할 수 없다는 안내를 보여준다.

#### 주문 목록 조회

[유저 스토리]
- 관리자는 전체 주문 목록을 조회할 수 있다.

[기능 흐름]
**전제 조건**
- 관리자만 이용할 수 있다.

**기능 요구사항**
- Main Flow
    - 전체 주문 목록을 20개씩 보여준다.
- Alternate Flow
    - 페이지 번호와 개수를 지정해 원하는 만큼 볼 수 있다.
- Exception Flow
    - 주문이 없으면 빈 목록을 보여준다.
    - 관리자 권한이 없으면 접근할 수 없다는 안내를 보여준다.

#### 주문 상세 조회

[유저 스토리]

[기능 흐름]
**전제 조건**
- 관리자만 이용할 수 있다.

**기능 요구사항**
