OFFICIAL

과제 공식 체크리스트

과제 명세 그대로의 합격 기준입니다. 이게 전부 체크되면 Must-Have 충족입니다.

쿠폰 도메인

  • 쿠폰은 사용자가 소유하며, 이미 사용된 쿠폰은 사용 불가 Coupon
  • 쿠폰 종류는 정액 / 정률로 구분, 각 적용 로직 구현 Coupon
  • 각 발급 쿠폰은 최대 1회만 사용 가능 Coupon

주문

  • 주문 전체 흐름에 대해 원자성 보장 Order
  • 사용 불가/존재하지 않는 쿠폰이면 주문 실패 Order
  • 재고가 없거나 부족하면 주문 실패 Order
  • 쿠폰·재고 중 하나라도 실패하면 모두 롤백 Order
  • 주문 성공 시 모든 처리가 정상 반영 Order

동시성 테스트

  • 동시 좋아요/싫어요 → like_count 정상 반영 Test
  • 같은 쿠폰 여러 기기 동시 주문 → 1회만 사용 Test
  • 같은 상품 동시 주문 → 재고 정상 차감 Test

① 쿠폰 발행 · 지급 (관리자)

  • Coupon 템플릿 엔티티 (name·type·value·minOrderAmount:Money·expiredAt·createdBy) — 관리자 API 생성

  • 사용자 GET /users/me/coupons · (셀프 발급·선착순은 백로그)

② 사용 + 주문 통합

  • OrderCreateCommand 에 couponId? 추가

  • 쿠폰 사용 = 낙관락(@Version), 충돌 시 주문 실패·전체 롤백

결정 사항 · 검증

아래는 고정된 결정입니다. 흔들리면 02·03 문서의 근거를 다시 봅니다.

사용 낙관락 @Version

단일 소유 row라 경합 드묾. 재고 비관락과 데드락 없음. 충돌 시 주문 실패.

발급 관리자 발행·지급

관리자가 발행·특정 유저에 지급. 단독 행위라 경합 없음. 셀프 발급·선착순은 백로그.

템플릿 관리자 API 생성

Coupon 은 /api-admin/v1/coupons 로 생성. 기존 admin 인증 재사용, 수정·삭제는 범위 밖.

테스트 MySQL

동시성 3종은 Testcontainers MySQL. H2는 락 의미 약함.

최종 검증

  • ./gradlew :apps:commerce-api:test 그린
