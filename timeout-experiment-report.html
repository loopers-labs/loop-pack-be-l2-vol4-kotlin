PG Timeout Experiment Report

TL;DR: PG 응답 지연을 2초까지 기다리던 정책을 700ms read timeout으로 낮춰, 지연 결제를 빠르게 UNKNOWN 상태와 복구 흐름으로 넘기도록 조정했다.

실험 목적

PG Simulator의 요청 지연 범위가 100ms~500ms인 점을 기준으로, 정상 지연보다 긴 1.2초 응답 지연이 발생했을 때 commerce-api 워커 스레드가 오래 점유되지 않도록 보호한다.

테스트 시나리오

PgSimulatorPaymentGatewayAdapterTest에서 로컬 PG stub 서버가 POST /api/v1/payments 응답을 1,200ms 지연한다. 어댑터는 해당 요청을 PaymentGatewayUnknownException으로 변환해야 하며, 측정된 클라이언트 대기 시간은 1,100ms 미만이어야 한다.

결과

구분 설정 결과 해석
Before connect 800ms / read 2s Red 테스트 실패. 1.2초 지연 응답을 성공으로 처리할 수 있음. PG 지연이 commerce-api 요청 지연으로 전파된다.
After connect 200ms / read 700ms Green 테스트 통과. 클라이언트 대기 시간은 테스트 기준 1,100ms 미만. 정상 PG 요청 지연 상한(500ms)에 200ms 여유를 두고 불확정 실패로 전환한다.

판단

700ms read timeout은 PG Simulator의 정상 요청 지연 상한 500ms보다 크고, 기존 2초보다 짧다. 따라서 정상 응답 여지는 남기면서, 지연 장애가 API 전체 응답 시간을 길게 끌고 가는 위험을 줄인다.
