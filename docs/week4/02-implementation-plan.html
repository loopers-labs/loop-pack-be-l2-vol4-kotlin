DOMAIN

쿠폰 도메인 모델

템플릿(Coupon)과 보유(UserCoupon)를 분리합니다. 정의는 불변, 생명주기는 사용자 소유 쪽에 둡니다.

핵심 도메인 메서드

DiscountPolicy.calculateDiscount(type, value, price) → MoneyPURE
FIXEDmin(value, price) (정액 · 캡)
RATEmin(price × value / 100, price) (정률 내림 · 캡)
캡price 를 받으니 할인 ≤ 주문금액을 여기서 보장
Coupon.validateUsable(orderAmount, now) → UnitPURE · 검증만
minOrderorderAmount < minOrderAmount → MIN_ORDER_NOT_MET
만료isExpired(now) → EXPIRED
책임자격 검증만. 계산은 DiscountPolicy 가 (Coupon 은 의존 안 함)
UserCoupon.use(now: LocalDateTime) → UnitSTATE
전이AVAILABLE → USED, usedAt 기록
거부AVAILABLE 아니면 COUPON_ALREADY_USED / EXPIRED
동시성@Version 이 동시 커밋 중 1건만 성공시킴 (2차 방어선)
결정할인 계산은 템플릿(Coupon)이, "사용 가능·1회성"은 UserCoupon이 책임집니다. 사용 락은 낙관락 — 근거는 03 동시성 노트.

ORDER

주문 통합 흐름

OrderService.place() 단일 트랜잭션 안에서 재고 차감 → 쿠폰 적용 → 주문 저장. 락 획득 순서가 데드락을 가릅니다.

OrderService.place() — 의사 흐름 
@Transactional
fun place(userId: Long, command: OrderCreateCommand): OrderInfo {
    // 1~2: 재고 비관락 + 차감 (기존)
    val inventories = inventoryRepository.findAllByProductIdInForUpdate(ids)
    snapshots.forEach { inv.decrease(it.quantity) }
    val originalAmount = Money(snapshots.sumOf { it.subtotal })

    // 3: 쿠폰 (couponId 있을 때만)
    val discount = command.couponId?.let { id ->
        val uc = userCouponRepository.findById(id) // 소유자 검증
        val coupon = couponRepository.findById(uc.couponId)
        coupon.validateUsable(originalAmount, now) // minOrder·만료 검증
        val d = DiscountPolicy.calculateDiscount(coupon.type, coupon.value, originalAmount) // 계산+캡
        uc.use(now) // @Version → 동시 사용 시 1건만
        d
    } ?: Money(0)

    // 4: 저장 (원금·할인·최종 스냅샷)
    return OrderInfo.from(orderRepository.save(
        Order.create(userId, snapshots, command.couponId, discount)))
}

4

YAGNI

만들지 않을 것

지금 필요 없는 것은 만들지 않습니다. 막판에 "혹시 몰라서"가 떠오르면 이 목록을 봅니다.

✕ 쿠폰 만료 배치

만료는 주문 시점 isExpired 검증으로 충분. 스케줄러 불필요.

✕ 쿠폰 수정·삭제 API

관리자 발행(생성)·지급만. 수정·삭제·풀 CRUD는 범위 밖.

✕ 쿠폰 사용 이력 테이블

주문 자체가 사용 기록. LikeEvent 식 append 불필요.

✕ like_count 추가 락

원자 UPDATE로 이미 해결. 락/버전 추가 금지.

✕ 보상 트랜잭션

트랜잭션 롤백이 처리. restore() 불필요.

✕ 다중 쿠폰 적용

요구는 1장. 조합 로직 금지.
