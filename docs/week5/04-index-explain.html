CANDIDATES

인덱스 후보

시나리오마다 필요한 인덱스가 다르다. 핵심 원칙: 동등 필터 컬럼을 앞에, 정렬 컬럼을 그 뒤에, 마지막에 타이브레이크 id.

쿼리 시나리오WHERE / ORDER BY필요 복합 인덱스
S1 인기상품status 필터 · like_count,id 정렬(status, like_count, id)
S2·S3 브랜드+좋아요brand_id 필터 · like_count,id 정렬(brand_id, like_count, id)
가격순(비교군)brand_id 필터 · price,id 정렬(brand_id, price, id)
최신순id DESCPK로 충분(추가 불필요)
방식 A 집계product_like 조인 키product_like(product_id)
왜 이 순서인가keyset 쿼리 WHERE brand_id=? AND (like_count,id)<(?,?) ORDER BY like_count DESC, id DESC는 brand_id로 진입 → (like_count,id) 정렬된 구간을 인덱스 순서대로 스캔한다. 컬럼 순서가 ORDER BY와 어긋나면 인덱스를 정렬에 못 쓰고 filesort로 떨어진다.
2

DILEMMA

status 선두 딜레마

status는 값이 ACTIVE/DELETED 둘뿐이고 대부분 ACTIVE다. 카디널리티가 낮은 컬럼을 인덱스 선두에 두는 게 맞을까? 정답은 EXPLAIN으로 가른다.

(a) status 선두

(status, like_count, id) — status 동등 후 정렬. DELETED가 소수면 OK. 인덱스 하나로 필터+정렬 해결.

(b) status 제외

(like_count, id)만 두고 status는 인덱스 후 필터. DELETED가 극소수면 오히려 단순·가벼움.

실험 항목(a)와 (b)를 둘 다 만들어 같은 S1 쿼리로 EXPLAIN 비교한다. 관전 포인트: rows examined, Extra 컬럼의 filesort 유무, 실제 시간(EXPLAIN ANALYZE). 낮은 카디널리티 컬럼의 선두 배치가 득인지 실인지를 숫자로 결론낸다.
3

COVERING

커버링 인덱스 여부

목록 응답이 필요한 컬럼을 인덱스가 전부 담으면 테이블 접근 없이 인덱스만으로 끝난다(커버링). 하지만 name 때문에 현실적이지 않다.

목록은 id, brand_id, name, price, like_count를 반환한다. 완전 커버링하려면 이 컬럼이 전부 인덱스에 들어가야 하는데, name은 VARCHAR라 인덱스를 비대하게 만든다.

채택 비커버링

인덱스로 정렬+필터 후 PK 룩업으로 본문. Using index condition. name 부담 없음 — 현실적 정답.

관찰용 커버링

name 빼고 (brand_id, like_count, id, price)면 부분 커버링 가능. Using index 관측은 되지만 효과 대비 인덱스 비용↑.

문서화 포인트"커버링은 가능하나 name 때문에 비용 대비 효과가 낮다"를 EXPLAIN의 Using index vs Using index condition 차이로 보여주고 트레이드오프로 기록한다.
4

MEASURE

EXPLAIN 측정 절차

인덱스를 수동 SQL로 토글하며 같은 쿼리의 전후를 찍는다. JPA 어노테이션은 ddl-auto=create와 충돌하니 측정 단계엔 쓰지 않는다.

측정 루프 — before → 인덱스 → after 
-- 1) BEFORE: 인덱스 없는 상태
EXPLAIN ANALYZE
SELECT * FROM product
WHERE brand_id = 1 AND status <> 'DELETED'
ORDER BY like_count DESC, id DESC LIMIT 20;
-- → Using filesort, rows examined ≈ 브랜드 모집단 전체

-- 2) 인덱스 생성
CREATE INDEX idx_brand_like_id ON product (brand_id, like_count, id);

-- 3) AFTER: 같은 쿼리 재실행
EXPLAIN ANALYZE /* 동일 쿼리 */;
-- → filesort 사라짐, rows examined ≈ LIMIT(20)

-- 4) 다음 실험 위해 제거
DROP INDEX idx_brand_like_id ON product;
