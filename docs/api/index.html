OVERVIEW

개요 · 읽는 법

commerce-api(단일 앱)가 외부로 노출하는 HTTP 엔드포인트는 총 8개, 4개 도메인입니다.

코드는 Clean Architecture 레이어(interfaces → application → domain → infrastructure)로 나뉘어 있고, 각 상세 페이지는 그 흐름을 레이어 시퀀스 다이어그램으로 그린 뒤 검증·예외·트랜잭션·동시성까지 설명합니다. 성공 응답은 모두 ApiResponseBodyAdvice 가 공통 ApiResponse(isSuccess · status · code · message · data · timestamp) 로 감쌉니다.

접근 권한 범례공개 — 인증 없이 호출(permitAll). · 인증 — X-Loopers-LoginId/X-Loopers-LoginPw 헤더를 AccountHeaderAuthenticationFilter 가 검증해 ACCOUNT_ID/LOGIN_ID 를 주입. · 관리자 — /api-admin/v1/**, AdminLdapAuthenticationFilter 가 X-Loopers-Ldap 헤더 + 자격증명 + role == ADMIN 까지 검증(아니면 401).
REST 미노출 내부 도메인brand · like · inventory 는 application/domain 계층만 존재하고 독립 컨트롤러가 없습니다. 브랜드명은 상품 상세에 실려 나가고(상품 상세 →), 재고 차감은 주문 생성 트랜잭션 안에서 일어납니다(주문 생성 →). commerce-batch/commerce-streamer 모듈은 HTTP 엔드포인트가 없습니다(배치 · Kafka).
2

ACCOUNT

계정

회원가입 · 내 정보 조회 · 비밀번호 변경. 외부 라우트는 /api/v1/users, 내부 도메인 명칭은 account 입니다.

메서드 · 경로설명접근문서
POST /api/v1/users 회원가입 — loginId · email · password · name · birthDate 검증 후 계정 + 자격증명 생성 공개 문서 →
GET /api/v1/users/me 내 정보 조회 — 인증된 사용자 본인의 프로필(이름 마스킹) 인증 문서 →
PUT /api/v1/users/password 비밀번호 변경 — 현재 비밀번호 검증 후 새 비밀번호로 교체 인증 문서 →
3

PRODUCT

상품

상품 목록(키셋 커서 페이지네이션) · 상품 상세. Week 5 "조회 병목 해결"의 핵심 읽기 경로입니다.

메서드 · 경로설명접근문서
GET /api/v1/products 상품 목록 — 정렬(LATEST · PRICE_ASC · LIKES_DESC) · 브랜드 필터 · 불투명 base64 커서 · size 1~100. 키셋(seek) 방식 공개 문서 →
GET /api/v1/products/{productId} 상품 상세 — 단건 조회 + 브랜드명 결합. 미존재 시 404 공개 문서 →
4

ORDER

주문

주문 생성. 상품 조회 · 금액 검증 · 쿠폰 적용 · 재고 차감(비관적 락)이 하나의 트랜잭션에서 일어나는, 가장 복잡한 교차 도메인 흐름입니다.

메서드 · 경로설명접근문서
POST /api/v1/orders 주문 생성 — 다중 상품 · 선택 쿠폰 · 기대 금액 3종 검증. 서버 재계산 불일치 시 409(PRICE_CHANGED), 재고 차감은 비관적 락. 상태 PENDING_PAYMENT 까지 생성 인증 문서 →
5

COUPON · ADMIN

쿠폰

쿠폰 정책 생성 · 사용자에게 발급. 둘 다 /api-admin/v1/** 관리자 전용 경로입니다.

메서드 · 경로설명접근문서
POST /api-admin/v1/coupons 쿠폰 생성 — 할인 타입(FIXED · RATE) · 값 · 만료일 · 최소 주문 금액. 발급 가능한 쿠폰 템플릿 정의 관리자 문서 →
POST /api-admin/v1/coupons/{couponId}/grant 쿠폰 발급 — 특정 사용자에게 지급(UserCoupon 생성). 만료 · 중복 발급 검증 관리자 문서 →
